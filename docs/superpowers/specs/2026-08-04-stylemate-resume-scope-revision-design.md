# StyleMate 简历级个人项目范围修订

## 1. 修订目标

StyleMate 定位为一个硕士生可在约 5 天内独立完成、能够公开演示并在面试中完整讲清楚的 AI 应用项目。项目重点是核心链路真实可用、界面完成度高、AI 输出可纠正、推荐结果来自用户真实衣橱，而不是追求企业级基础设施的完备程度。

本文取代原设计中尚未实施的 Task 4–9；已经完成并验证的运行时配置、数据模型、会话/SQLite 存储和衣物图片入库工作流继续保留。

## 2. 用户可感知的核心链路

公开演示只保留一条清晰主线：

1. 用户进入 Streamlit 应用，可直接加载 6 件样例衣物，也可上传自己的 JPG/JPEG、PNG 或 WebP 图片。
2. 有视觉模型密钥时，系统识别名称、类别、颜色、材质、季节和风格；无密钥或识别失败时进入手动填写。
3. 用户确认或纠正识别结果后，衣物才进入衣橱。
4. 用户在衣橱页查看、筛选、编辑和删除单品。
5. 用户选择场景、城市/天气和风格偏好，系统从当前衣橱中生成 1–3 套搭配。
6. 每套搭配只引用真实存在的衣物，并展示推荐理由、天气提示和简短约束检查。

这条链路就是首页和 README 的主叙事，不增加注册、社交、电商或复杂运营功能。

## 3. 保留的工程能力

- 保留 Streamlit，不新增 FastAPI、Vue、React 或移动端。
- 保留 demo 与 local 两种运行模式：公开演示使用会话内存，本地模式可使用 SQLite。
- 保留两个项目内 Python 工作流：
  - 衣物识别与入库工作流；
  - 基于库存的穿搭规划工作流。
- 保留必要的超时、一次重试、手动兜底、图片路径安全和隐私保护。
- 保留少量高价值测试：上传校验、图片隔离、识别兜底、库存一致性、规则推荐和应用冒烟测试。

这些工作流是普通 Python 类，不创建 Codex SKILL.md，也不搭建通用 Skill 框架。

## 4. 明确删除或降级的范围

- 不做账号、权限、组织、多租户或远程数据库。
- 不做复杂 Agent 编排、长期记忆、审批流或工具注册中心。
- 不做独立的 Agent Trace 中心；只在推荐结果下提供一个简短的“生成过程”折叠面板。
- 不做完整评测平台或评测中心页面；只保留一个离线脚本和一份 JSON 结果。
- 不做复杂反馈分析与历史看板；最多保留一个简单收藏按钮。
- 不继续扩展已有聊天 Agent；可作为辅助入口保留，但不作为简历主卖点。
- 不增加监控、审计、缓存、队列、并发控制或企业级故障矩阵。

## 5. 简化后的界面

Streamlit 使用四个清晰区域：

- **今日搭配**：项目说明、样例数据入口和最近一次推荐。
- **我的衣橱**：上传、AI 识别、人工纠正、筛选与编辑。
- **搭配助手**：场景、城市和偏好表单，以及 1–3 套库存内推荐。
- **关于项目**：技术栈、轻量评测结果、隐私说明和 GitHub 链接。

界面追求统一配色、清晰卡片、空状态和移动端基本可读性，不实现复杂设计系统。

## 6. 穿搭推荐方案

推荐采用“确定性规则 + 可选大模型润色”的个人项目方案：

1. 按场景、季节、类别和风格筛选当前衣橱；
2. 组合上装、下装、鞋履和可选外套；
3. 对库存完整性、场景匹配和天气适配进行简单打分；
4. 没有文本模型密钥时直接返回规则理由；
5. 有密钥时仅润色理由，不允许模型新增衣物 ID。

这既能展示 AI 应用集成，也保证公开演示没有密钥时仍可运行。

## 7. 轻量评测

离线评测固定约 10 个案例，只计算三个容易解释的指标：

- inventory_valid_rate：推荐衣物 ID 是否全部来自候选衣橱；
- constraint_pass_rate：场景、类别和基础天气约束是否满足；
- fallback_success_rate：无密钥或外部服务失败时是否仍返回可用结果。

评测脚本输出 artifacts/evaluation.json。README 和简历只引用实际执行产生的结果，不设置独立评测页面。

## 8. 公开演示与简历交付

- 使用 Streamlit Community Cloud 或同等轻量平台部署。
- 公共 demo 模式默认加载样例衣橱，不要求注册。
- 没有视觉/文本模型密钥时，上传流程进入手动填写，穿搭使用规则引擎。
- README 包含一张主界面截图、运行说明、架构概览、真实评测结果和限制说明。
- 简历描述聚焦“多模态识别 + 人工纠正 + 库存约束推荐 + 无密钥降级 + 公开演示”，不使用企业级或平台级措辞。

## 9. 剩余实施范围

剩余工作压缩为三个任务：

1. 完成 Streamlit 衣橱工作台和演示模式；
2. 完成库存约束搭配推荐与简短生成过程；
3. 完成轻量评测、README、截图、部署配置和公开链接验证。

完成这三个任务后即停止扩展，转入学术文献助手项目。
