# StyleMate 产品化升级设计

日期：2026-07-28

目标岗位：AI 应用开发

实施周期：5 天

交付形态：Streamlit 公开演示应用

## 1. 背景与问题

StyleMate 已具备 ReAct Agent、ChromaDB RAG、用户画像、天气工具、会话持久化和 Plan-SelfReflect 等能力，但当前产品入口仍是“登录后聊天”。底层能力无法被用户直接感知，也缺少真实衣橱资产、结构化搭配结果、可追溯执行过程、失败降级和量化评测，因此演示效果更接近聊天玩具而非完整 AI 应用。

本次升级不重写技术栈，不增加电商、社交或模型训练等无关范围。核心目标是把现有能力组织成一条可使用、可解释、可评测、可公开演示的数字衣橱闭环。

## 2. 产品目标与成功标准

### 2.1 产品目标

用户能够完成以下完整流程：

1. 无需注册即可进入访客示例模式。
2. 上传衣物图片，由多模态模型识别品类、颜色、材质、季节和风格。
3. 检查并修改识别结果，将衣物保存到数字衣橱。
4. 输入场景、日期或城市等需求。
5. 系统结合真实库存、用户画像、天气和 RAG 知识生成搭配。
6. 用户查看推荐依据和 Agent 执行轨迹，并收藏或反馈结果。
7. 开发者通过评测中心查看识别、约束满足和失败恢复表现。

### 2.2 成功标准

- 公开演示在没有 API 密钥或外部接口异常时仍可完成示例闭环。
- 视觉识别结果必须先通过结构化字段校验，用户可以在入库前修改。
- 所有推荐单品都必须引用衣橱中真实存在的衣物 ID，库存幻觉数量为 0。
- 天气、RAG 或模型调用失败时，页面返回明确的降级结果而非报错堆栈。
- Agent 执行轨迹能够说明使用了哪些上下文、工具和校验步骤，但不得暴露密钥、完整系统提示词或敏感信息。
- 项目包含可重复运行的单元测试、Skill 测试和离线评测集。
- README 只展示真实运行后得到的指标、截图和部署链接。

## 3. 范围

### 3.1 本轮包含

- Streamlit 衣橱工作台
- 访客示例模式与本地完整模式
- 衣物图片上传与多模态识别
- 衣物标签人工修正、去重和入库
- 数字衣橱卡片、筛选与删除
- `WardrobeOnboardingSkill`
- `OutfitPlanningSkill`
- 天气、用户画像、RAG 和库存联合推荐
- 结构化搭配卡片、收藏和负反馈
- 可展开的 Agent 执行轨迹
- 异常降级、测试和离线评测面板
- Streamlit Community Cloud 公开部署

### 3.2 本轮不包含

- 电商购买、支付、社交分享
- 推荐模型训练、微调或复杂排序模型
- FastAPI、Vue 或 React 重写
- 原生移动端
- 生产级多租户、权限和计费系统
- 长期可靠的公共云用户数据存储

## 4. 信息架构与页面

采用“衣橱工作台”而非三步向导作为主布局。

### 4.1 概览

- 展示衣物数量、可用搭配数和近期衣物使用情况。
- 展示基于天气和常用场景生成的今日搭配。
- 提供“上传衣物”和“生成完整搭配”快捷入口。
- 首次访问自动载入示例衣橱，不强制注册。

### 4.2 我的衣橱

- 上传 JPG、JPEG、PNG 或 WEBP 图片，单张不超过 8 MB。
- 展示视觉模型识别结果和字段置信度。
- 低置信字段高亮，允许用户修改后确认入库。
- 按品类、颜色、季节和风格筛选衣物。
- 支持查看、编辑和删除衣物。
- 重复图片根据内容哈希提示合并或取消。

### 4.3 智能搭配

- 输入场景、日期或城市、风格偏好及额外约束。
- 默认从当前衣橱选取单品，不生成不存在的商品名称。
- 返回 2 至 3 套结构化搭配，每套包含衣物 ID、推荐理由、天气适配和注意事项。
- 支持收藏与“不喜欢”反馈；反馈原因采用固定选项加补充文本。
- 提供默认折叠的 Agent 执行轨迹。

### 4.4 搭配收藏

- 展示已收藏搭配及其组成衣物。
- 允许取消收藏。
- 公共访客数据只在当前会话有效；本地完整模式持久化保存。

### 4.5 评测中心

- 面向项目演示和开发调试，不作为普通用户主入口。
- 展示识别字段完整率、库存真实性、约束满足率、失败恢复率和响应时间。
- 支持运行内置离线评测集。
- 明确区分目标值与本次实际运行结果。

### 4.6 对话助手

- 保留现有对话能力，但降级为辅助页面。
- 对话可以调用两个核心 Skill 以及现有尺码、洗护和知识检索工具。
- 聊天不再承担衣橱管理和结果展示的全部职责。

## 5. 系统架构

系统分为五层。

### 5.1 交互层

Streamlit 负责页面导航、表单、衣物卡片、搭配卡片、执行轨迹和评测面板。页面只调用业务服务，不直接操作 JSON、SQLite、模型或外部接口。

### 5.2 业务服务层

- `WardrobeService`：上传校验、去重、标签修正、衣物增删改查。
- `OutfitService`：收集上下文、调用搭配 Skill、校验结果、保存收藏与反馈。
- `ProfileService`：读取、合并和更新用户画像，处理偏好冲突。
- `EvaluationService`：运行离线用例、聚合指标、生成评测报告。

每个服务职责单一，并通过明确的数据模型与页面和 Skill 通信。

### 5.3 Agent Skill 层

Skill 是面向业务目标的确定性工作流，负责组合模型、工具、校验和降级逻辑。ReAct Agent 负责识别意图并选择 Skill；普通页面可以直接调用 Skill，避免所有请求都经过自由规划。

### 5.4 AI 与工具层

- 配置驱动的 DashScope 多模态模型：识别衣物图片。
- 现有 DashScope 文本模型：意图理解、搭配生成和自然语言解释。
- ChromaDB RAG：检索穿搭、面料和洗护知识。
- 高德天气工具：提供当前天气和预报。
- 现有规则工具：尺码、洗护、衣橱缺口和风格分析。

模型名称通过环境配置注入，业务代码不硬编码具体版本。

### 5.5 数据层

业务层只依赖 Repository 接口。

- `SessionWardrobeRepository`：公开访客模式使用，数据在 Streamlit 会话内隔离，自动载入示例衣橱。
- `SQLiteWardrobeRepository`：本地完整模式使用，保存衣物元数据、用户画像、收藏、反馈和运行记录。
- `LocalImageStore`：本地完整模式保存上传图片；公开模式仅保存会话期临时图片。
- 现有 ChromaDB 继续保存知识库向量。

该设计不承诺 Streamlit Community Cloud 上的访客数据长期持久化。
运行模式由 `APP_MODE=demo|local` 显式选择；公开部署使用 `demo`，本地默认使用 `local`。

## 6. 核心数据模型

### 6.1 Garment

- `id`
- `name`
- `category`
- `primary_color`
- `material`
- `seasons`
- `styles`
- `image_ref`
- `image_hash`
- `confidence`
- `source`
- `created_at`

`category`、`primary_color`、`seasons` 和 `styles` 为必填字段；其他字段允许为空但必须显式表示。
`source` 只能取 `ai`、`manual` 或 `sample`，用于区分实时识别、手动录入和示例数据。

### 6.2 OutfitRequest

- `scene`
- `target_date`
- `city`
- `style_preference`
- `extra_constraints`
- `candidate_garment_ids`

### 6.3 OutfitRecommendation

- `id`
- `garment_ids`
- `score`
- `reason`
- `weather_note`
- `constraint_checks`
- `knowledge_sources`
- `created_at`

`garment_ids` 必须全部存在于当前 Repository；保存前执行强制校验。

### 6.4 AgentTrace

- `skill_name`
- `steps`
- `tool_calls`
- `fallbacks`
- `duration_ms`
- `status`

轨迹保存摘要信息，不记录密钥、完整提示词或上传图片二进制。

## 7. 核心 Skill 设计

### 7.1 WardrobeOnboardingSkill

**目标：** 将一张衣物图片稳定地转换为可编辑、可保存的结构化衣物记录。

**输入：**

- 图片字节、MIME 类型和文件名
- 可选用户补充描述

**步骤：**

1. 校验图片类型和大小。
2. 计算内容哈希并查询重复记录。
3. 调用多模态模型提取结构化字段。
4. 使用 `Garment` 模型校验字段。
5. 对低置信或缺失字段生成修正提示。
6. 将草稿返回页面供用户确认。
7. 用户确认后通过 `WardrobeService` 保存。

**降级：**

- 模型调用失败或结构化解析失败时自动重试一次。
- 第二次失败后返回空白手动录入表单，不丢失已上传图片。
- 检测到重复时不自动覆盖，由用户决定取消或作为新记录保存。

### 7.2 OutfitPlanningSkill

**目标：** 只使用真实衣橱库存，结合场景、天气、画像和知识库生成可解释搭配。

**输入：**

- `OutfitRequest`
- 用户画像
- 当前衣橱快照

**步骤：**

1. 解析硬约束与软偏好。
2. 获取天气；失败时使用缓存或季节信息。
3. 按品类、季节和场景筛选候选库存。
4. 从 RAG 检索相关穿搭知识。
5. 调用文本模型生成 2 至 3 个结构化候选方案。
6. 校验所有衣物 ID、场景约束和天气适配。
7. 丢弃无效方案；没有有效结果时调用规则搭配器。
8. 排序并生成面向用户的解释与 `AgentTrace`。

**降级：**

- 天气失败时继续使用季节和用户输入。
- RAG 无命中时使用规则知识，不伪造知识来源。
- 文本模型失败时使用规则搭配器。
- 公开演示无密钥时使用预置输入和预置结构化结果。

## 8. 数据流

### 8.1 衣物入库

上传图片 → `WardrobeService` 校验 → `WardrobeOnboardingSkill` → 多模态识别 → `Garment` 校验 → 用户修正 → Repository 保存 → 衣橱卡片刷新。

### 8.2 智能搭配

用户请求 → `OutfitService` → 获取画像、库存、天气和 RAG 上下文 → `OutfitPlanningSkill` → 生成候选 → 库存与约束校验 → 规则降级或排序 → 搭配卡片与执行轨迹 → 收藏或反馈。

## 9. 错误处理与安全

- 上传前校验扩展名、MIME 类型和 8 MB 文件大小上限。
- 页面捕获业务异常并显示用户可理解的信息，不显示堆栈。
- 天气请求超时设为 5 秒，模型请求超时设为 30 秒；模型结构化失败只自动重试一次。
- 外部 API 密钥仅从环境变量或 Streamlit Secrets 读取。
- `.env` 与 `.streamlit/secrets.toml` 不得提交到 Git。
- Agent 轨迹对提示词、密钥和敏感参数进行脱敏。
- 公共模式不展示其他访客的图片、衣橱或历史。
- 演示模式在无密钥时明确标识“示例结果”，不得伪装成实时调用。

## 10. 测试与评测

### 10.1 单元测试

- `Garment` 和 `OutfitRecommendation` 结构化校验
- 图片类型、大小和哈希去重
- Repository 增删改查
- 用户画像合并与冲突处理
- 候选衣物筛选
- 库存真实性校验
- 规则降级搭配器

### 10.2 Skill 测试

- 使用模拟多模态模型测试成功、缺字段、无效 JSON、超时和重试。
- 使用模拟天气、RAG 和文本模型测试正常搭配与各类降级。
- 验证每条成功推荐的衣物 ID 均存在。
- 验证每种外部服务异常都返回结构化、可理解的结果。

### 10.3 离线评测集

- 至少 15 张具有不同品类、颜色和材质的衣物样例。
- 至少 10 个覆盖通勤、面试、约会、旅行和日常休闲的搭配场景。
- 天气超时、RAG 无命中、模型无效输出和无密钥等异常用例。

### 10.4 指标

- 视觉识别必填字段完整率
- 视觉识别字段人工修正率
- 推荐库存真实性
- 场景和天气硬约束满足率
- 外部服务失败恢复率
- 端到端响应时间

库存真实性的验收值为 100%；失败恢复用例必须全部返回结构化降级结果。其他指标在完成实现后实际运行并写入 README，不在设计阶段预设虚假成绩。
